# PRD — FOF (친구의 친구를 소개합니다)

## 1. 서비스 개요
- **서비스명**: FOF (Friend Of Friend)
- **한 줄 소개**: 아예 모르는 사람이 아닌, 지인의 지인을 소개해 주는 소개팅 서비스
- **운영 방식**: 관리자가 "친구들"을 등록·관리하고 직접 매칭해 준다. (자동 매칭 없음)
- **용어**: 서비스에 등록된 소개팅 당사자를 **친구(friend)** 라고 부른다.

## 2. 사용자
| 구분 | 설명 | 시점 |
|---|---|---|
| 관리자 | 친구 등록/조회/삭제 및 매칭 진행. 현재 2명, 수동 등록 | MVP~2단계 |
| 친구 | 소개팅 당사자. 직접 로그인하지 않으며 관리자가 정보를 입력 | 데이터로만 존재 |

## 3. 단계별 범위

### Phase 1 — MVP
1. **친구 등록**
2. **친구 목록 조회 + 필터** (성별, 출생연도 범위)

### Phase 2 — 권한/관리자
1. 간편 로그인 (카카오 또는 구글, 확정 전)
2. 관리자 권한: 관리자 2명은 DB에 수동 등록 (화이트리스트)
3. 관리자 페이지
   - 등록 항목 추가 / 삭제 / 필수·선택 변경
   - 등록된 친구 삭제

### Out of scope (당분간 하지 않음)
자동 매칭, 친구 본인 로그인, 채팅, 결제, 알림

## 4. MVP 상세 요구사항

### 4.1 친구 등록
| 항목 | 필수 | 타입 | 검증/비고 |
|---|---|---|---|
| 이미지 | 선택 | 파일 | jpg/png/webp. 선택 시 브라우저에서 자동 압축(최대 1600px, JPEG)하여 업로드, 서버 상한 5MB, 원본은 30MB까지 선택 가능. Supabase Storage |
| 이름 | **필수** | 문자열 | 1~30자 |
| 성별 | **필수** | 선택 | 남 / 여 |
| 키 | **필수** | 정수(cm) | 100~230 |
| 나이(출생연도) | **필수** | 정수(0000년생) | 1950 ~ (올해 − 19)년생. 성인(만 19세)만 등록 가능 |
| 종교 | 선택 | 문자열 | 무교/기독교/천주교/불교/기타 중 선택 (확정 필요) |
| 직업 | **필수** | 문자열 | 1~50자 |
| 거주지 | 선택 | 문자열 | 최대 50자 (시/구 단위 자유 입력, 확정 필요) |
| 성격 | 선택 | 긴 문자열 | 최대 500자 |
| 이상형 | 선택 | 긴 문자열 | 최대 500자 |

- 저장 성공 시 목록으로 이동, 실패 시 필드별 에러 메시지 표시
- 나이는 "나이"가 아닌 **출생연도**로 저장한다 (해가 바뀌어도 값이 변하지 않음)

### 4.2 친구 목록 조회
- 카드(또는 테이블) 형태로 표시: 이미지, 이름, 성별, 출생연도, 키, 직업, 거주지
- 최신 등록순 기본 정렬
- **필터**
  - 성별: 전체 / 남 / 여
  - 출생연도: 시작 ~ 종료 (예: 1994 ~ 1998년생). 한쪽만 입력해도 동작
  - 필터 값은 URL 쿼리스트링으로 유지 (새로고침/공유 가능) — `?gender=female&from=1994&to=1998`
- 결과 없음 상태(empty state) 표시

## 5. 비기능 요구사항
- **개인정보**: 소개팅 당사자의 개인정보를 다루므로 외부 공개 접근을 막아야 한다 → [미결 사항 #1](#7-미결-사항) 참고
- 모바일 우선 반응형 (관리자가 모바일로 쓸 가능성이 높음)
- 이미지는 Storage에 저장, DB에는 경로(URL)만 저장

## 6. 성공 기준 (MVP)
- 관리자가 5분 안에 친구 1명을 등록할 수 있다
- 성별/출생연도 조합 필터가 정확히 동작한다

## 7. 미결 사항
| # | 질문 | 제안 |
|---|---|---|
| 1 | MVP 단계(로그인 없음)에서 개인정보 노출을 어떻게 막을까? | 배포 URL 비공개 + 공유 비밀번호 게이트(env) 또는 MVP부터 로그인을 앞당기기. DB는 RLS로 anon 접근 차단하고 서버(Server Action)에서만 접근 |
| 2 | 로그인 수단: 카카오 vs 구글 | 관리자 2명 모두 쓰는 계정으로 결정. 구현 난이도는 구글이 낮음 |
| 3 | 종교/거주지 입력 방식 | 종교는 선택지, 거주지는 자유 입력 |
| 4 | 이미지 노출 범위 | 비공개 버킷 + signed URL 권장 |
